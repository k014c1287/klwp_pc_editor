# UXフィードバック対応TODO

作成日: 2026-08-02  
入力資料: `商用ツール比較_UX改善課題.md`  
対象: KLWP Desktop Editor 現行master

## 1. 判定基準

指摘は、次の順で妥当性を判断する。

1. 現行コードと実際の画面に該当する不足があるか
2. `sample/` とKLWPの保存意味を壊さず実装できるか
3. 過去に合意した操作安全性と矛盾しないか
4. 独立したレビュー・テストができるPR単位へ分けられるか
5. 商用感だけでなく、日常編集の時間短縮または誤操作防止へ寄与するか

## 2. 指摘の妥当性評価

| 指摘 | 判定 | 根拠と対応方針 |
| --- | --- | --- |
| ダークテーマ、余白、ホバー | 妥当 | 現在はOS標準ttkと暗いキャンバスが混在する。外部テーマ依存を増やさず、組込みテーマと配色層で統一する |
| ツールバーのアイコン | 妥当 | 全ボタンが文字のみ。環境依存の画像アセットを増やさず、安定表示できる記号＋ラベルを導入する |
| アプリアイコン、スプラッシュ | 条件付き | ブランド素材と配布形式が未決定。スプラッシュは起動を遅く見せる可能性もあるため、今回のTODO外 |
| ウェルカム画面、テンプレート | 妥当 | 起動時に空の編集画面だけが表示される。sampleを上書きしない複製読込として実装する |
| 最近使ったファイル | 妥当 | 現在は履歴なし。アプリ設定をKLWP成果物と分離して保存する |
| 時計が進むライブ再生 | 妥当 | LOOP/SWITCH再生はあるが、`preview_ts` は固定され時計数式が進まない |
| 0～24時スクラバー | 妥当 | 日時はダイアログの文字入力だけ。既存の時刻依存Global評価を直接体験できるUIがない |
| キャンバスクリック選択 | 今回は不採用 | 「未選択時や別要素クリックで選択を奪わない」という明示仕様と衝突する。左ツリー選択後の直接移動・リサイズは既に可能 |
| 整列、分配 | 妥当 | スナップはドラッグ補助で、複数選択の確定配置コマンドとは用途が異なる |
| 右クリックメニュー | 妥当 | 頻出レイヤー操作への近道がなく、メニューバーとの往復が必要 |
| 数値スクラビードラッグ | 条件付き | Undoのまとめ方、入力フォーカス、アンカー符号の設計が必要。単独の操作設計を先に行うため今回のTODO外 |
| レイヤーサムネイル | 条件付き | 動的要素や大規模ツリーで描画コストが高い。キャッシュ戦略を決めるまで保留 |
| 表示／非表示トグル | 妥当 | `config_visible` と非表示タグは既にあり、保存意味も確定している |
| ロック | 条件付き | Komponentの `internal_locked` と一般要素の編集ロックを同一視できない。実sampleで一般要素の形式を確認するまで保留 |
| 共通不透明度スライダー | 今回は不採用 | Shapeは色alpha、Bitmapは`bitmap_alpha`など型ごとに保存先が異なる。共通値で上書きすると未知設定を壊す可能性がある |
| ツールチップ | 妥当 | 常用ツールバーの発見性向上としてテーマPRへ含める |
| Ctrl+Kコマンドパレット | 妥当 | メニュー項目が増えており、機能名から探す入口として有効 |
| トースト通知 | 条件付き | 保存・転送結果はstatusへ表示済み。まずツールチップとコマンド検索を優先し、通知API統一後に再評価する |
| 空状態メッセージ | 対応済み | 右ペインに「要素が選択されていません／次の要素はルートへ追加」と表示済み |
| 部品ライブラリ | 条件付き | 永続形式、依存画像・フォント、Global衝突規則を先に定義する必要があるため保留 |
| カラースウォッチ | 条件付き | 保存先をアプリ設定にするかKLWP Globalにするか未決定。Globalとの統合方針を決めてから対応 |
| PNG書き出し | 妥当 | `render_to_image()` が既にあり、独立した小さいPRで利用者機能へ昇格できる |
| ピクセル差分ビューア | 条件付き | 現在は開発・品質保証CLIとして機能する。一般利用者向けの実機画像取得フローを決めるまで保留 |
| Broadcastプレースホルダ露出 | 妥当・不具合 | 既定値が意図的な英語プレースホルダで、かつ編集UIに項目がない。既定は空、必要時はプレビュー値で入力可能にする |

## 5. 今回保留した事項の再開条件

- アプリアイコン: ブランド名、配色、配布形式が決まる
- スプラッシュ: 起動時間計測で待ち時間を隠す必要が確認される
- 数値スクラビー: Undoの連続入力集約仕様が決まる
- レイヤーサムネイル: 大規模sampleで許容できるキャッシュ方式が決まる
- ロック: 一般要素に対するKLWP実データの保存キーが確定する
- 共通不透明度: モジュール型ごとの変更先と数式優先順位が定義される
- 部品ライブラリ: 依存アセットとGlobal衝突の移植規則が定義される
- カラースウォッチ: アプリ設定とKLWP Globalのどちらを正とするか決まる
- トースト: status更新を一つの通知APIへ集約できる
- ピクセル差分ビューア: 実機スクリーンショットの取込導線が決まる
